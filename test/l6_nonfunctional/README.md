# L6 非功能测试

本层尚未实现脚本，原因是**基线需要先在测试机上实测校准**——凭空写出的
阈值（如"P95 < 50 ms"）没有意义，反而会给出虚假的可信度。

## 待实现清单

| 类型 | 用例 | 建议基线（待实测校准） |
|---|---|---|
| 性能 | 单文件删除拦截延迟 | P95 与未加载驱动时对比，增幅需有上限 |
| 性能 | 目录树删除（5000 文件） | 总耗时 ≤ 未加载驱动基线 × 2（RB-19 缓存生效） |
| 性能 | 队列洪峰 | 512 打满时孤儿数 0，拒绝数可观测 |
| 压测 | 持续删除 24 h | 无句柄/池/内存泄漏，计数器不溢出 |
| 故障注入 | 服务 kill -9 | 驱动不崩；重启后对账恢复，无孤儿 |
| 故障注入 | DB 锁死/损坏 | 服务告警，不删用户数据；备份可恢复（RB-11） |
| 故障注入 | 磁盘满 | fail-closed，`DeleteDenied` 增长，数据不丢 |
| 故障注入 | 驱动卸载中删除 | 不蓝屏（RB-28 路径） |
| 长稳 | 7×24 h 混合负载 | 无崩溃、无孤儿、DB 体积可控（归档生效） |
| 安全 | token 时序、审计、限流 | 对应 RB-16 各子项 |

## 实现前置

1. 先完成 L4/L5 的测试机建设（快照 + Verifier + dump + 符号）
2. 用未加载驱动的场景跑一遍，作为**对照基线**（没有对照组的性能数字无意义）
3. 再实现本层脚本，阈值取自实测 P95 而非估算

## 故障注入的注意事项

- `磁盘满` 建议在**独立小容量卷**上用配额/占位文件模拟，避免真的填满系统盘
- `DB 损坏` 用副本操作，绝不直接破坏生产库（先备份）
- `kill -9` 后必须验证对账恢复，这正是 RB-05 的核心路径
